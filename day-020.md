# Day 020

## Topics Studied
- GitHub Issues: creation, labels, and best practices
- GitHub Project Boards (Kanban)
- Referencing and automatically closing issues through commits and pull requests
- Introduction to milestones

## What I Learned
I learned how to organize development tasks using GitHub Issues, categorize them with labels, and manage their progress with a Project Board. I also learned how GitHub automatically closes issues when a merged pull request includes a closing keyword such as `Closes #6`.

## Practice
- Created four issues in the **cardapio-digital** repository with appropriate labels
- Created a GitHub Project Board with **To Do**, **In Progress**, and **Done** columns
- Completed the workflow: **issue → branch → commit → pull request → automatic issue closure**

## Challenges
Understanding how issues, branches, pull requests, and the Project Board work together required some experimentation. Correctly configuring automatic issue closure also required attention to GitHub's closing keywords.

## Notes
GitHub Issues and Project Boards provide a structured workflow for tracking tasks and managing project progress. Automatic issue closure helps keep the project organized and up to date.
