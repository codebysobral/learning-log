# Day 022

## Topics Studied

* `git reflog`
* `git reset --soft`, `--mixed`, and `--hard`
* Recovering "lost" commits
* Risks and best practices for each reset type

## What I Learned

I learned how `git reflog` records recent `HEAD` movements, making it possible to recover commits even after a hard reset. I also understood the differences between the three reset modes and when each one should be used safely.

## Practice

* Simulated a lost commit using `git reset --hard`
* Recovered the commit with `git reflog` and created a branch from its hash
* Compared the behavior of `git reset --soft` and `git reset --mixed`

## Challenges

Remembering the effects of each reset mode on the staging area and working directory, especially the difference between `--mixed` and `--hard`.

## Notes

`git reflog` is a valuable safety net for recovering commits that are no longer referenced by the current branch. Using `git reset --hard` requires extra caution because it permanently discards uncommitted changes.
