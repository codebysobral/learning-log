# Day 025

## Topics Studied
- Repository forks
- Difference between `origin` and `upstream`
- Complete open source contribution workflow
- Best practices for first-time contributions to third-party projects

## What I Learned
Today I learned how the open source contribution workflow works using a fork. I understood the difference between `origin` (my fork) and `upstream` (the original repository), how to keep my fork synchronized, and the complete process of creating a branch, making commits, pushing changes, and opening a Pull Request. I also learned the importance of following project contribution guidelines, writing clear commit messages, and keeping changes small and focused.

## Practice
- Forked an open source repository.
- Configured the `origin` and `upstream` remotes.
- Synced my fork with the original repository.
- Created a feature branch.
- Made changes, committed them, and pushed the branch.
- Opened a Pull Request to the original repository.

## Challenges
At first, understanding when to use `origin` and `upstream` was confusing. After practicing the workflow, I clearly understood their different purposes and how they work together.

## Notes
- Always create a new branch before making changes.
- Keep the fork synchronized with the upstream repository.
- Follow the project's contribution guidelines.
- Write clear and meaningful commit messages.
- Keep Pull Requests small and focused to simplify reviews.
